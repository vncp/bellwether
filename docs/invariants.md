# Invariants

A sentence that must be true of the system at all times, paired with the test that fails if it stops being true. A PR that touches an invariant updates its test in the same PR.

| # | Invariant | Enforced in | Test |
|---|---|---|---|
| 1 | **No false negatives in pruning.** If a row group contains a queried key, the `ScanPlan` includes it. Holds for exact, bloom, range, and temporal paths. | `bellwether-core`; end to end in `bellwether-build` | property test over random layouts and key sets: `core/tests/no_false_negatives.rs`; through the builder and the plan builder: `build/tests/invariants.rs` |
| 2 | **A Receipt implies a passing Certificate.** The ledger refuses to store a Receipt whose certificate does not resolve, did not pass, did not verify the receipt's proposal, or was not computed against `manifest_before`; whose replay was not computed against `manifest_before`; or whose `manifest_after` is not a sequence later than `manifest_before` (equal only for Rewrite proposals) and no later than the current one. Sequences compare numerically (ADR 020). Maintenance commits (GC, compaction) may advance the sequence between apply and attest, so "current" is an upper bound, not an equality. Stage 4 is apply then attest. | `bellwether-ledger` | `ledger/tests/forged_receipt.rs` attempts each violation |
| 3 | **Replay is deterministic.** Same manifest version + same workload hash + same proposal + same `inputs` (the catalog digest of the data read) ⇒ byte-identical `Replay`. Two replays over different data differ in `inputs`, even when both are unindexed and name manifest version "0". | `bellwether-replay` | golden test: `replay/tests/determinism.rs` |
| 4 | **Readers see one manifest version.** A build in progress never changes what a concurrent reader observes. | `bellwether-store` | `store/tests/snapshot_isolation.rs` interleaves commit and read |
| 5 | **Stale-version rejection.** A temporal lookup never returns a superseded row, even when the newest version lives in a row group pruned for another reason. The index-wide max per key is consulted before ranking. | `bellwether-core`; end to end in `bellwether-build` | `core/tests/temporal_stale_rejection.rs`; through the plan, including a newest version pruned by another spec and one whose file was rewritten: `build/tests/invariants.rs` |
| 6 | **Evidence and Certificates carry provenance.** Every `Evidence` and `Certificate` names the inputs it was derived from, their age, and an RFC 3339 creation time; the ledger rejects one with no inputs or a malformed time. A `Certificate` must also name the manifest version it was computed against. For `Evidence` the manifest version is optional, because a profile of an unindexed folder has no manifest yet. | `bellwether-ledger`, `bellwether-profile` | `ledger/tests/provenance_required.rs`; `profile/tests/provenance.rs` (every profile Evidence cites resolvable inputs and is refused without them) |

Invariant 5 closes a known failure mode of latest-version lookups: ranking only the rows that survived pruning can promote a superseded row. It is an invariant here from the first commit.
