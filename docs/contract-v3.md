# Contract v3 backlog

Gaps in `bellwether-types` (contract v2) and in the docs that the Phase 2 authors hit while implementing build, profile, and replay. Each entry names who raised it, what the crate does today, and the proposed resolution. Nothing here is decided until it lands as an ADR or a format amendment; until then the interim behaviour stands. Contract v3 opens after M3 (`docs/evolve.md` §10), and every change below is additive or a documented error, never a silent reinterpretation.

| # | Gap | Raised by | Interim behaviour | Proposed resolution |
|---|---|---|---|---|
| 1 | `Replay` has no field naming the cost model of a layout replay, although `RunCost` requires one | replay | landed 2026-10-24 as contract v2.1: `Replay.model` and `Replay.inputs`, `RECORD_VERSION` 2, ledger rule on kind consistency | done |
| 2 | The replay crate has no defined replay for rewrite proposals, although the ledger accepts one (exact, or modelled with a named model per ADR 027) | replay | the replay crate refuses to score a rewrite | define the rewrite replay as the before and after plan costs over the recorded runs for file-backed steps, and a measured cost with a named model for database-backed steps |
| 3 | `KeySpec::name()` omits `fpr` and `ts_column`; manifests key segments and completeness by name | build, replay | two specs sharing a name are refused; a same-name redefinition is a full rebuild; caches key on the full spec plus a catalog digest | define a canonical full-spec identity string in `format.md` and use it everywhere a name is used |
| 4 | The manifest has no per-row-group byte counts; plans open every Parquet footer | build, replay | footers are read at plan time; text uses recorded chunk lengths | record `bytes` per row group in the manifest at build time (already in `RowGroupMeta`) |
| 5 | `Fanout` carries no sample size or error bound | profile | the error is stated in the message text | add `sample_size` and `quantile_error` fields |
| 6 | `EvidenceBody::Profile` has no fields for sortedness, range overlap, or time scatter | profile | reach the Evidence only through lints | add a `columns` table of per-column measurements |
| 7 | `Lint` has no typed field for the recommended fix | profile | the composite lives in `message` | add `fix: Option<RewriteShape>` (the catalog already maps each rule to one) |
| 8 | The manifest `source` has no CSV dialect fields | build | encoded in `source.kind` as `csv;delimiter=…;header=…` | typed `dialect` fields |
| 9 | Column types are stored as Arrow `Display` strings, which can change across Arrow versions | build | a round-trip test pins the spelling | define a stable spelling in `format.md`; the Phase 3 upgrade must keep it parseable |
| 10 | `Source` has no identity or configuration method, so a text source's chunk size is invisible to callers | profile, build | callers pass `source_config`; the build uses concrete types | add `Source::identity() -> SourceIdentity` |
| 11 | `Predicate` cannot cap `asof` from above, and `And` has no stated evaluation order | build | the plan adds `Between(ts, lowest winner, asof)` and documents the order: filters, then `NotOlderThan`, then `LatestPerKey` | write the order into `format.md` and the `Predicate` docs; consider an explicit `AsOf` predicate |
| 12 | "Row groups covered" was read two ways: ids processed (build) or ids that produced keys (core) | build | build's reading, so all-null row groups count as covered | state build's reading in `format.md`; core's range field is renamed or documented as keyed-only |
| 13 | The planner's serving, per-key intersection, and signed-zero rules exist only in the build and replay READMEs | build, replay | both crates document and test the same rules | promote to `format.md` or an ADR once PR review confirms the two READMEs agree |
| 14 | The recorded workload carries no query kind, so only `locate` runs are priced | replay | `latest` and `asof` runs are not modelled | add `kind` per run to the workload format |
| 15 | "Template" is undefined for per-template reports | replay | recorded per run, defaulting to `locate(<columns>)` | define template as the run's key columns plus kind |
| 16 | Latency budgets "registered in bench" conflict with the layering, which forbids bench from depending on engine crates | build, replay | each crate asserts its own budget in an optimized-build test and a criterion bench | decided: the owning crate asserts its budget; the CLI-level `bench` subcommand runs them all |
| 17 | `build(root, key_specs, …)` removes specs not listed | build | declarative removal, reported in `specs_removed` | under review: removal must be an explicit option or call, never implied by omission |
| 18 | Files that vanish are not covered by ADR 013 | build | treated as drift: ids retired, fresh ids if the file returns | amend ADR 013 with this rule |
| 19 | Changing the fingerprint policy or the recorded chunk size of a tracked file | build | refused (policy) or kept per file (chunk size) | amend `format.md` "fingerprint policy" with both rules |
| 20 | The bench workload hash is `u64`-specific; replay's hash covers any key type | replay | both are verified on read; they differ by design | one definition in `format.md` once the workload format has a kind field (#14) |
| 21 | `RunCost.exact` is a boolean, but joins and ranges are bounded rather than exact or measured | ADR 026 | `exact: false` with the model named in text | a tri-state `Exactness { Exact, Bounded { low, high }, Measured }` |
| 22 | `ScanEntry` has no per-column bytes, so projection cost cannot be priced from a plan | ADR 026 | plan `bytes` is the row-group total | add `columns: Vec<(String, u64)>` to `ScanEntry` |
| 23 | `Predicate` has no join or window variant | ADR 026 | joins are expressed as a semi-join over a key set | add `SemiJoin { columns, keys_from }`, `Join { left, right, columns }`, `WindowPartition { columns }` |
| 24 | Exact segments store presence, not counts | ADR 026 | cardinalities are bounded by row counts per row group | storage version 2: optional per-key counts beside the bitmap |
| 25 | `CertBody` has no field for per-key mismatch examples, so a reader of a failed certificate cannot see which keys differed | verify | examples live only in the typed result | add `examples: Vec<MismatchExample>` capped at a documented count |
| 26 | `CertBody` has no counter for keys that could not be compared (every version has a null timestamp) | verify | counted in `mismatched`, stated in the README | add `uncomparable: u64` |
| 27 | `Coverage` does not define "keys compared" per kind, nor how a realized sample fraction is computed | verify | workload: distinct supplied keys; sampled: sampled keys present; the requested fraction when no keys exist | define both in the `Coverage` docs and record the realized fraction |
| 28 | The group string in `totals_delta` has no specified format | verify | canonical JSON naming the total column and the group values | specify it in `format.md` |
| 29 | A certificate over two unindexed folders has no manifest to name | verify | manifest version "0" with both catalog digests in provenance inputs (decided 2026-10-24, matching replay) | make the convention explicit in the `Provenance` docs |
| 30 | The catalog digest (the data identity replays and certificates cite) was computed in two crates | replay, verify | verify moves it to `bellwether_source::catalog::digest` with pinned bytes and a `format.md` definition; replay adopts it in a follow-up after both merge; the facade asserts both paths agree | one definition in the source crate |
| 31 | `Replay` carries no list of the specs that formed the current configuration, so a reader cannot see that an incomplete declared spec dropped out of "current" | replay review | documented in the replay README; plans listing such a spec are refused | add `configuration: Vec<String>` (full spec identities) to `Replay` |
| 32 | Memory caps in build and replay count accounted key bytes, not resident memory (about 290 resident bytes per key for an open writer; the layout map undercounts by 15 to 25%) | replay review | the replay README states the measured ratios and that `max_segment_rows` is the effective bound for narrow keys | a calibrated per-key overhead shared by both crates, measured in CI |

| 33 | Dataset schema inference takes the first file's decimal scale, so a folder whose files use different scales is accepted or refused depending on file order | facade review | the facade offers a schema override and names it in the error | infer decimal precision and scale as the widest across all files, deterministically, in the source crate |
| 34 | `why` with keys writes engine Proposals and Replays, while the threat model lists `observe.*` as writing nothing | facade review | allowed for the CLI; MCP must decide | WP12 places `observe.why` without keys in observe and with keys in a separate engine-scored tier, and the threat model table says so |
