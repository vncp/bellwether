# Measured results: the files behind every chart

Each `*.json` here is written by one script and read by
[`scripts/render_charts.py`](../../../scripts/render_charts.py), which renders
the charts in `docs/assets/results-*-{light,dark}.svg` and the tables between
`<!-- results:<block>:begin -->` and `<!-- results:<block>:end -->` markers in
the README and under `docs/`. Nothing those outputs show is typed by hand; CI
(`render_charts.py --check`) fails when a chart or table differs from what the
committed results render.

| File | Written by | Rendered as |
|---|---|---|
| `showcase.json` | [`scripts/showcase.sh`](../../../scripts/showcase.sh) | README "Results"; `results-bytes`, `results-replay`, `results-latency`, `results-reconcile`; the tables of [2026-10-25-showcase.md](../2026-10-25-showcase.md) |
| any other `<source>.json` | its own script | one chart per numeric metric, `results-<source>-<metric>-{light,dark}.svg`, and a table for the block `results:<source>` wherever that marker appears |

## Schema

One JSON object per file:

```json
{
  "source": "perf",
  "generated_by": "scripts/<script that wrote it>",
  "rows": [
    {
      "dataset": "taxi",
      "query": "taxi-zones-week",
      "side": "duckdb",
      "metric": "bytes",
      "value": 341861576,
      "unit": "bytes",
      "exactness": "measured",
      "machine": "Apple M3 Pro, 12 cores, 36 GB, macOS 26.4.1, local SSD",
      "build": "DuckDB v2.0.0 (d54cbbe3df)",
      "date": "2026-10-25"
    }
  ]
}
```

Every row carries all ten fields:

- `dataset`, `query`: what was asked. `query` is a stable id; a source may describe its ids in an optional top-level `queries` object (`showcase.json` gives `text`, `kind`, `keys`, and the `sql`).
- `side`: who answered: `full-scan`, `duckdb`, `bellwether-…`, or the source's own names. A chart draws one bar per side.
- `metric`, `unit`: `bytes`/`bytes`, `row_groups`/`row groups`, `wall_ms`/`ms`, `rows_per_s`/`rows/s`, … Use one unit per metric.
- `value`: a number, or a string or boolean for records (a receipt hash, a `fix` outcome, whether two answers matched). Only numbers are charted.
- `exactness`: `exact` when the value cannot change between runs on the same data (footer sums, plans, counts, hashes); `measured` when it is a timing or a profiler reading.
- `machine`, `build`, `date`: where, with what, and when (UTC date). `build` names the binary that produced the value (a Bellwether release build and its commit, DuckDB's version, or `footer statistics (no engine)`).

Optional top-level `datasets` maps a dataset id to `{"name", "label", …}`; `name` is the short form charts use.

No production data and no production numbers, ever: every dataset is public or generated by a seeded script in this repository.
