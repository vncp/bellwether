# Changelog

All notable changes are documented here. The format follows Keep a Changelog; versions follow Semantic Versioning. Until 1.0, the on-disk format version in `bellwether-types::format` is the compatibility contract, not the crate version.

## [Unreleased]

### Added

- ADR 033 amendment (PR #24 review, round 2): ClickHouse runs the agent's text with `readonly=1`, so a `SETTINGS` clause (a cache turned on, or the logging of profile events and settings turned off) is refused by the engine; a log entry not fully logged (empty `ProfileEvents`, or `Settings` without the request's `readonly=1`) is refused (`statistics_missing`). Kusto takes an export's result rows from its own `.export` response (`NumRecords`, the same run); `Exported` gains `rows`.
- `bellwether-source-engine` (WP20b, ADR 033): query engines that own their storage as measured sources. A `MeasuredEngine` adapter trait of exactly three primitives (`submit(query, tag)`, `stats(tag)` from the engine's own query log, `export(handle, dir)` as Parquet), a `Source` over the engine's storage units with an identity, and `EngineScorer` (WP20's `MeasuredScorer`). Adapters: ClickHouse (reference; `system.query_log`, `FORMAT Parquet`, `readonly=2`, one unit per partition; tested end to end against a server container in CI) and Kusto (`.show queries` by `ClientRequestId`, `.export to parquet`, extents as units, the Azure Identity credential chain; tests skip without a cluster). The crate README sketches BigQuery, Snowflake, and Postgres as one file each.
- The engine loop through the facade, CLI, and MCP: `workload record <lake> --from-engine <uri> --keys-query <file>` (MCP `score.record`); `why --twin-of <uri> --gate NAME:N` reports per candidate the keyset against each gate, rows per key, and files per key, says the diagnosis is on a copy, records the engine's identity beside the lake's sequence, and adds four twin lints (low-cardinality key, unbounded membership, wide-before-narrow, dedup-before-filter; advice only); `propose --rewrite before.sql=after.sql` (repeatable; must cite twin Evidence); `fix --twin-of <uri> --scratch <dir> [--keep]` on a rewrite scores every query in the engine (a measured Replay with the twin's prediction, written first), exports each pair and reconciles it by the proposal's key columns into one Certificate citing the engine's identity before and after, and writes an attest-only receipt; the apply tier measures again. `receipt show` lists `apply=attest-only`, `costs=measured, not exact`, and the prediction; `report --html` marks measured costs with their model and adds a prediction-error table.
- Contract (additive, every new field skipped when empty, so earlier records keep their hashes): `RunCost.measured` (`QueryStats`), `Replay.prediction` and `Receipt.prediction` (`Prediction`), `Receipt.attest_only`, `RewriteShape.pairs`/`key`/`keys` (`QueryPair`), `EvidenceBody::Profile.twin` (`TwinOf`, `Gate`), `Error::ExportDenied`. Ledger rules: measured current costs only on a rewrite naming its model; a cost with engine statistics is never exact; a receipt over a measured replay is attest-only, leaves the manifest unchanged, and carries its replay's prediction. MCP refusal codes `export_denied` and `caller_supplied_cost` (a score, cost, measurement, replay, prediction, verdict, or certificate field in any tool's arguments is refused by name, called directly or as a job). `docs/format.md` "Query engine sources" with conformance vectors; ADR 033.
- ADR 033 amendment (PR #24 review): the trait is `submit(query, tag)`, `export(query, tag, dir)` (one run, whose rows are exported: the rows verified are the rows measured), and `stats(run)`, which must find the run's own log entry (its text, its user, one finished entry, not cache-served; Kusto reads `.show commands-and-queries`) or refuses with the new `Error::MeasurementRefused` and MCP code `measurement_refused` (`cache_served`, `statistics_missing`, `not_the_query_submitted`, `ambiguous_log_entry`, `tag_mismatch`, `result_rows_differ`). The apply tier re-reads the engine's identity after its measurement, refuses a measurement that disagrees with the certified replay (`Refusal::MeasurementChanged`, MCP `measurement_changed`), and runs the gain gate. A rewrite must rest on the twin's recorded key sample (`keys`). The scratch folder must be a hidden folder under the lake root, created with its permissions. `Prediction` holds each pair's reads and ratios (`pairs: Vec<PairPrediction>`) instead of sums. A root with a literal secret is redacted to scheme, host, and path.
- `bellwether-source-sql` (WP20, ADR 027): SQL tables as sources. `sql://<engine>/<schema>.<table>?db=...` roots over SQLite (rusqlite, in process), DuckDB, Postgres, and Flight SQL (ADBC), and SQL Server (ODBC, feature `odbc`); declared partitions or key ranges as units with an identity (a version column's maximum or a checksum of the unit's statistics); statistics as bounds from one aggregate query per unit; exact conversion to the dataset type; one snapshot per run, or every identity re-read and a change refused (`source_changed`); a `MeasuredScorer` (wall time, `EXPLAIN ANALYZE`). Through the facade, CLI, and MCP: reconcile a table against files (the certificate cites both catalog digests and the table's identity), `why` with every cost measured and no Replay recorded, `fix` verifying and then refusing with `attest_only` naming the `CREATE INDEX` to run (no Receipt). Folder-only verbs over a table refuse with `not_a_folder`. `scripts/sql-demo.sh` measures it on the NYC taxi data.
- README rewritten product-first: a wordmark, one measured line from the Results under the promise, what you can do with it, the `why` capture in "In one minute", a thirty-second start, how it works, the Results unchanged, then one section per capability, each paired with a real terminal capture (`fix` and a failing `reconcile`, `report`, bitemporal `asof`, an MCP refusal over stdio); each idea is stated once. `scripts/readme-captures.sh` generates its data with `bellwether bench`, runs every command shown in a pseudo-terminal, and stores the text beside each image; `scripts/render_terminal.py` draws the captures and `scripts/render_figures.py` the wordmark, loop, and architecture figures, both in light and dark. CI fails when a capture or figure no longer matches its committed source. The loop figure moves to `docs/assets/readme/` and the three-step figure is removed (it repeated the numbered steps); the evolve design is summarized in one paragraph linking `docs/evolve.md`.
- README "Results": realistic questions on NYC taxi, GH Archive, ClickBench, and a synthetic market corpus, each answered by a full scan, DuckDB alone, and DuckDB on Bellwether's plan after `why` → `fix`, plus `reconcile` against DuckDB `EXCEPT ALL` (`scripts/showcase.sh`). Every chart and table is rendered from `docs/measured/results/*.json` by `scripts/render_charts.py` (schema in `docs/measured/results/README.md`), and CI fails when a committed chart or table no longer matches the committed results. The ClickBench transcript moves from the README to `docs/measured/2026-10-24-clickbench.md`; downloads are shared with `scripts/realdata.sh` through `scripts/datasets.sh`.
- Signed receipts (WP19, ADR 029): `Ledger::sign`, `signatures`, `verify_against`, and `explain_verified` over detached ed25519 objects `ledger/<hash>.sig.<key id>.json`; `bellwether keys generate|show|trust`; `fix --signing-key` (or `BELLWETHER_SIGNING_KEY`, a path) signs the receipt and certificate it wrote; `--trusted-keys` (or `BELLWETHER_TRUSTED_KEYS`) on `receipt show`, `ledger receipts`, and `report` gives verdicts (`signed`, `untrusted`, `unsigned`, `invalid`); `receipt show --require-signature` exits 1 unless every link is intact, the receipt and its certificate are signed by a trusted key, and the evidence is about this data root (signatures bind content, not location); key and trust files inside the index location are refused; the MCP server takes `--signing-key` and `--trusted-keys`, and each envelope chain carries `signatures` and `verdict`. No record or storage version changes.
- Release measurements (WP22a): `scripts/perf.sh` (with `scripts/perf.py`, `perf-report.py`, `perf-budgets.py`) measures lookups against a full scan and DuckDB, build throughput by thread count, reconcile throughput by memory budget, replay and observe latency, and resident bytes per key, profiles the hot paths with samply, and writes `benches/out/perf.json` (`bellwether-perf/1`); published in `docs/measured/2026-10-26-performance.md` (with its `2026-10-26-perf.json` and `2026-10-26-samples.jsonl`, the binary's sha256 and source commit, ranked WP22b hypotheses from the profiles, and a reconcile memory finding: peak RSS and footprint past the stated bound at small budgets on wide row groups) with `docs/measured/budgets.toml` and the chart rows `docs/measured/results/perf.json`. The verify README states the measured one-pass budgets and the memory finding; the build and replay READMEs and contract v3 entry 32 state the measured resident bytes per key. Budgets leave out DuckDB's times and meter peaks, and cap reconcile peak memory at the stated bound. `bellwether index --threads N` sets the build's worker count (the segments written do not depend on it); `bellwether bench read --plan|--all` reads planned row groups through the benchmark's byte-counting reader.
- `bellwether-mcp` (WP12): the MCP server over stdio (`bellwether-mcp`, and `bellwether mcp` with the same flags from one definition), tools in observe, score, propose, apply, and jobs tiers over the facade, each tool's text the CLI's `--json` line (ADR 010). Refusals carry a stable code, facts, and a `next` line in MCP field names; the facade's typed errors (`RecordNotFound`, `WrongKind`, `NoWorkload`, `NotIndexed`, `InvalidArgument`) name the argument to fix. Per-session budgets admit score and apply calls one at a time by reservation; a job id always names one result; a key already complete is refused before it is scored, so the apply dry run and the apply agree and the refusal writes nothing.
- `bellwether` (the facade, WP9): one `Engine` whose operations (`why`, `index`, `locate`, `latest`, `asof`, `propose`, `reconcile`, `fix`, `receipt`, `report`) return typed results that are the CLI's `--json` output and what the MCP server returns (ADR 010).

### Fixed

- README "Results": the market questions are measured with the corpus's `day=` directories as a partition column on every side, through `fix` (which now records `--partitioning`); `scripts/showcase.sh` always reads the market corpus that way, and its `--market-hive` flag is gone.
- `fix` built a new index without the folder's partitioning, so a later
  `locate --partitioning hive` (or `--path-template`) was refused as "built
  with partitioning none". `index` and `fix` now share one set of build
  options (`Engine::build_options`), which records the scheme in
  `manifest.source`.
- `propose --key temporal2:id@valid,known` (and `exact:a@ts`) failed with
  "unknown kind". `propose` now reads `--key` as `index --key` does, and
  refuses a sidecar with a typed refusal (exit 3, MCP
  `sidecar_not_proposable`) that names the `index` command that builds it.
  MCP `propose.key` also takes the short form.
- `--chunk-size` on a Parquet folder was accepted by `why` and `propose`
  and refused by `index` and `fix`; every verb now refuses it as a usage
  error (exit 2) naming `--format csv|jsonl`.
- CI workflow never ran: GitHub rejects `hashFiles()` in a job-level `if`.
  Replaced with step-level presence checks.
