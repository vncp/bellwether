# Changelog

All notable changes are documented here. The format follows Keep a Changelog; versions follow Semantic Versioning. Until 1.0, the on-disk format version in `bellwether-types::format` is the compatibility contract, not the crate version.

## [Unreleased]

### Added

- Release binary workflow (`.github/workflows/release.yml`, WP17): builds `bellwether` (`crates/bellwether-cli`, `--release --locked`) for `x86_64-unknown-linux-gnu` (`ubuntu-latest`), `aarch64-unknown-linux-gnu` (`ubuntu-24.04-arm`), and `aarch64-apple-darwin` (`macos-14`), packages each binary at the archive root as `bellwether-<tag>-<target>.tar.gz`, computes `checksums.txt`, verifies `action/install.sh` against the built Linux archive and `checksums.txt` using a local `gh` stand-in, uploads the archives and `checksums.txt` as workflow artifacts, and publishes them to the GitHub Release on `v*` tag pushes. `action/tests/install-checksum.sh` (wired into `.github/workflows/ci-action.yml`) tests `action/install.sh`'s release-download and `checksums.txt` verification path against valid, tampered, missing, and duplicate checksum entries.
- `bellwether-adapters` (WP16, ADR 010's second half): the plan `locate`, `latest`, and `asof` emit, executed inside a query engine. One `Adapter` trait (`emit(plan, schema, opts) -> Artifact`) with three engines: **DataFusion 55** (feature `datafusion`): one `ParquetAccessPlan` per file (planned row groups `Scan`, the rest `Skip`), DataFusion's own pruning off, the scan behind a leaf no optimizer pushes into, an exact `metadata_size_hint` with `--footer-hint`; the residual as a logical plan; `CountingStore` records what DataFusion asked for and what the store served, classified per file into data, footer, and other bytes. **DuckDB 2.0**: one SQL statement over the planned files, restricted to the planned row groups' rows by `file_row_number` (DuckDB cannot pin row groups; its bytes are measured, never asserted equal). **Spark 4.2**: a manifest and `shims/spark/bellwether_plan.py` (`read(spark, manifest_path)`); only planned-file access is claimed. The residual is decoded at the dataset types (new `bellwether_core::encoding::decode`, exact: re-encodes to its bytes or refuses) and run in the plan's order: filters, `NotOlderThan` (a per-key bound joined on the key), `LatestPerKey` (`rank() = 1`: every tie at the newest timestamp kept, null keys and timestamps never win), then `Live`. Float keys compare as canonical bytes in DataFusion (`-0.0` apart from `+0.0`); a residual an engine cannot run exactly is refused by name with the engine that can (DuckDB refuses a NaN key, which its Parquet statistics would silently drop; DuckDB and Spark refuse `Text`, `ExprIn`, and one-signed float zeros). Measured at the storage boundary: DataFusion's data bytes equal the plan's and its touched row groups are the planned ones; DuckDB touches every planned row group; Spark opens no unplanned file. The DataFusion description loads back with `datafusion::from_json`, which refuses one edited after it was printed.
- `locate`, `latest`, `asof ... --emit datafusion|duckdb|spark [--keys-file-in-query] [--residual full|keys-only|none] [--ordered] [--footer-hint] [--engine-pruning] [--relocate FROM TO] [--out PATH]`: the artifact after the plan line, or in a file; nothing is executed. `--ordered` is refused with the plan's reason when it has no read order. `crates/bellwether-cli/tests/emit.rs` indexes a bench corpus, emits every lookup for every engine, runs each artifact as written, and checks its rows and exact `amount` total against the bench oracle; CI's `check` job installs the DuckDB CLI v2.0.0 and a new `spark` job installs Java 17 and PySpark 4.2.0, and each fails if an engine test is skipped. The planned-versus-realized byte table (release, measured at the storage boundary) is in `crates/bellwether-adapters/README.md`. Layering gains `bellwether-adapters -> bellwether-types, bellwether-core` and `bellwether-cli -> bellwether-adapters`.
- `bellwether ci` and the composite GitHub Action `action/action.yml` (WP17): a changed pipeline step needs a receipt, and the gate is the receipt hash. `.bellwether/ci.toml` (read from the base commit only) declares the ledger, `gate = "require" | "advise"`, `require_signature` with a committed trust file, and steps (name, path globs, the root the receipt is about, the workload it must cover). Receipt hashes come from `.bellwether/receipts/<step>` at the head or a `Bellwether-Receipt(<step>): <hash>` body line, both strictly 64-hex. The facade's `Engine::receipt_gate` checks, in order, kind, chain, the certificate (the ledger's receipt rules 12 to 16 re-run, never `explain`'s intact flag), coverage, the step root's catalog digest now (`data_changed`), and signatures on the receipt and its certificate, and returns the first failure with its facts; `Engine::ci_gate` returns the `GateReport` that `--json` prints. Without a receipt under `advise` with `[ci] why = true`, `why` over the step's workload. One comment per pull request, found and updated by `<!-- bellwether-ci -->`, also written to the step summary. Exit codes 0 pass/advisory/nothing to check, 1 a step failed, 2 usage or configuration, 4 the ledger could not be read. The Action downloads a release binary checked against the release's `checksums.txt`, or builds its own ref (`version: build`); nothing from the pull request runs. The threat model gains its CI row; `crates/bellwether-cli/README.md` lists the exit codes; `bellwether::parse_trusted_keys` reads a trust file's text.
- Relational replay (WP15, ADR 026 amended, ADR 005 amended): a consumer's query as a typed plan DAG (`ConsumerPlan`: `scan`, `filter`, `semi_join`, `join`, `latest`, `as_of`, `window`, `aggregate`, `exchange`, `project`; never SQL) priced node by node from the index and footers, each node's bytes and output rows `exact`, `bounded` (an interval holding the truth), or `measured`; the README's "Pricing a whole query" table lists every operator. Shared nodes are evaluated once per run, each scan read once with the union of its consumers' row groups. Joins merge both indexes' sorted key blocks; a join side without an exact or temporal key on its join columns is refused (`JoinNotIndexed`). `why --plan <file> --dataset NAME=ROOT` (global; also bound when an MCP server starts) prices a workload through the plan beside an operator table; MCP `score.why` takes `plan`, `datasets` (names the human bound, never a root), and `at`. A run names its plan by hash (`RecordedRun.plan`, omitted when absent so existing workload hashes stay). `why` judges the layout culprit of plan runs by where the runs' own keys sit on the folder, not by the plan's reads; when the plan reads everything though the keys sit in few row groups, the culprit is the plan's shape (`CulpritReason::PlanShape`), naming the node that applies the run's keys and the `aggregate` or `join` below it. `propose --before-plan --after-plan` (MCP: `shape.before_plan`/`after_plan`) gives a rewrite typed plans: `fix` scores both, reconciles the actual outputs, and writes an attest-only receipt, refusing `data_changed` if a dataset changed since the score; `no_replay` remains only for a rewrite stated in prose. A key proposal over a plan workload is verified on the keys (or range) the plan looks up through it, and refused (`invalid_argument`) with what to do when a plan looks it up over the whole key space, looks nothing up through it, or makes lookups one certificate cannot compare (whole keys beside ranges, ranges on several columns, several key-column sets, every row of some keys beside the newest version of others). `bellwether bench relational` writes the two-dataset corpus (`events`, `repos`) with key files and plans. The ledger refuses a replay whose run cost is exact while a node is measured (rule 7b).
- Scope decision (ADR 032 amendment, 2026-10-27): `advise` (WP13a) is reduced to workload-level key-set selection, exact knob descent, Pareto with anchors, and receipts, and starts after WP22b's lookup fix; layout and materialization search, edge and plan-node attribution, `evolve --llm` (WP13b), rulebook v2 (WP13c), and the transfer evaluation (WP18) are deferred until a recorded multi-step pipeline workload exists. WP15 no longer carries plan-node counterfactuals or layout pricing. README "Planned: evolve" becomes "Planned: advise"; M6 and M8 restated; `docs/evolve.md`, `docs/work-packages.md` (status as of 2026-10-27), and the `layout_not_applicable` wording in the CLI and facade docs follow.

- Tombstone plan counters name their measured quantities: `keys_without_row_groups` and `key_row_group_pairs_pruned` count pruned candidates, not retracted winners or distinct row groups. Incomplete-sidecar diagnostics distinguish direct `index` repair from the optional verified `fix` workflow.

- ADR 033 amendment (PR #24 review, round 2): ClickHouse runs the agent's text with `readonly=1`, so a `SETTINGS` clause (a cache turned on, or the logging of profile events and settings turned off) is refused by the engine; a log entry not fully logged (empty `ProfileEvents`, or `Settings` without the request's `readonly=1`) is refused (`statistics_missing`). Kusto takes an export's result rows from its own `.export` response (`NumRecords`, the same run); `Exported` gains `rows`.
- `bellwether-source-engine` (WP20b, ADR 033): query engines that own their storage as measured sources. A `MeasuredEngine` adapter trait of exactly three primitives (`submit(query, tag)`, `stats(tag)` from the engine's own query log, `export(handle, dir)` as Parquet), a `Source` over the engine's storage units with an identity, and `EngineScorer` (WP20's `MeasuredScorer`). Adapters: ClickHouse (reference; `system.query_log`, `FORMAT Parquet`, `readonly=2`, one unit per partition; tested end to end against a server container in CI) and Kusto (`.show queries` by `ClientRequestId`, `.export to parquet`, extents as units, the Azure Identity credential chain; tests skip without a cluster). The crate README sketches BigQuery, Snowflake, and Postgres as one file each.
- The engine loop through the facade, CLI, and MCP: `workload record <lake> --from-engine <uri> --keys-query <file>` (MCP `score.record`); `why --twin-of <uri> --gate NAME:N` reports per candidate the keyset against each gate, rows per key, and files per key, says the diagnosis is on a copy, records the engine's identity beside the lake's sequence, and adds four twin lints (low-cardinality key, unbounded membership, wide-before-narrow, dedup-before-filter; advice only); `propose --rewrite before.sql=after.sql` (repeatable; must cite twin Evidence); `fix --twin-of <uri> --scratch <dir> [--keep]` on a rewrite scores every query in the engine (a measured Replay with the twin's prediction, written first), exports each pair and reconciles it by the proposal's key columns into one Certificate citing the engine's identity before and after, and writes an attest-only receipt; the apply tier measures again. `receipt show` lists `apply=attest-only`, `costs=measured, not exact`, and the prediction; `report --html` marks measured costs with their model and adds a prediction-error table.
- Contract (additive, every new field skipped when empty, so earlier records keep their hashes): `RunCost.measured` (`QueryStats`), `Replay.prediction` and `Receipt.prediction` (`Prediction`), `Receipt.attest_only`, `RewriteShape.pairs`/`key`/`keys` (`QueryPair`), `EvidenceBody::Profile.twin` (`TwinOf`, `Gate`), `Error::ExportDenied`. Ledger rules: measured current costs only on a rewrite naming its model; a cost with engine statistics is never exact; a receipt over a measured replay is attest-only, leaves the manifest unchanged, and carries its replay's prediction. MCP refusal codes `export_denied` and `caller_supplied_cost` (a score, cost, measurement, replay, prediction, verdict, or certificate field in any tool's arguments is refused by name, called directly or as a job). `docs/format.md` "Query engine sources" with conformance vectors; ADR 033.
- ADR 033 amendment (PR #24 review): the trait is `submit(query, tag)`, `export(query, tag, dir)` (one run, whose rows are exported: the rows verified are the rows measured), and `stats(run)`, which must find the run's own log entry (its text, its user, one finished entry, not cache-served; Kusto reads `.show commands-and-queries`) or refuses with the new `Error::MeasurementRefused` and MCP code `measurement_refused` (`cache_served`, `statistics_missing`, `not_the_query_submitted`, `ambiguous_log_entry`, `tag_mismatch`, `result_rows_differ`). The apply tier re-reads the engine's identity after its measurement, refuses a measurement that disagrees with the certified replay (`Refusal::MeasurementChanged`, MCP `measurement_changed`), and runs the gain gate. A rewrite must rest on the twin's recorded key sample (`keys`). The scratch folder must be a hidden folder under the lake root, created with its permissions. `Prediction` holds each pair's reads and ratios (`pairs: Vec<PairPrediction>`) instead of sums. A root with a literal secret is redacted to scheme, host, and path.
- Storage version 2 and record version 3, first of two pull requests (WP14/B1, ADR 028). This one makes the record version 3 shapes final; the second freezes the bytes of storage version 2 (M5):
  - **Per-key counts.** Per-key, per-row-group counts on exact and temporal specs (`--key exact:col,counts`, `temporal:id@ts,counts`). `bellwether count --keys` and MCP `observe.count` answer `count(*) where key in (...)` exactly, with rows and row groups, and read no data file. Plans through a counted spec carry exact `rows`. `why` prices `exact:<cols>,counts` for the columns of every count run no current spec counts, notes it as "count runs answered from per-key counts, no data read", and recommends it when it reads fewer bytes. Rule `R-counts-1` finds a count query that precedes a query over the same keys, unless a spec the planner counts with (counted, on exactly those columns in any order, exact or temporal) is declared. Two listed segments of one counted spec that both count a (key, live row group) are refused as a corrupt index, never summed, and the refusal says to run `index`, which finds a counted spec two of whose segments cover one live row group and rebuilds it (`specs_repaired`, and a `rebuilt …` line).
  - **Checksums.** XXH3-64 over every segment region a read touches, so a corrupt byte is refused, never read as a wrong count.
  - **Manifest statistics.** `rowgroup_rows`, `rowgroup_bytes` and `column_bytes` per file, so a plan opens no Parquet footer. `locate --columns` prices a projection exactly (`ScanEntry.columns`, `ScanPlan.projected_bytes`); over a version 1 manifest it reads the planned files' footers and says how many (`column_bytes_from_footers`). A `--columns` naming an unknown, empty or repeated column is a usage error (exit 2).
  - **Identity keys.** Segments and completeness are keyed by the full-spec identity (`KeySpec::identity()`), so `bloom:id@0.01` and `bloom:id@0.05` never share them. A new declaration naming a key or time column that contains `,` or `@` is refused, so no two specs declared from now on share an identity; a spec an index already declares is read and indexed as it is (a version 1 index on a column `a,b` reads and upgrades), and only two declared specs that actually share an identity (version 1 allowed two temporal specs whose time column holds an `@`) stop the upgrade, with the step that resolves it (re-declare one under its name), before anything is read or written. Errors name specs by identity, never by Rust debug output.
  - **Record version 3 shapes:** `Exactness` and `Quantity` on costs (ledger rule 7b reads `exactness`; a query engine's measured cost is `exactness: measured` with its log as the model, `rows` absent), `CertBody.{examples, uncomparable, totals, row_filter}` (rule 9 passes only with `uncomparable == 0`), `Replay.configuration`, `ScanPlan.order`, `Fanout.{sample_size, quantile_error}`, `Lint.fix`, `ProposalBody::Key.sidecars`, the join and window predicates, and `ConsumerPlan`, pinned by a golden with every field set; `docs/format.md` gains sidecar proposal vectors.
  - **Later version 2 shapes refused.** A version 2 manifest or segment in a shape only the second pull request writes (a column `data_type` map, `source.dialect`, a key spec with `bounds`, a bitemporal spec or layout) is refused by name with `Error::UnsupportedShape` (exit 4, MCP `unsupported_version`), which says to upgrade.
  - **Version 1 indexes.** They are read; an `index` with nothing to do leaves them at version 1, the first build with work upgrades the manifest and says so, and a commit that fills no statistics (compaction, garbage collection) keeps a version 1 manifest at version 1.
  - **Fixtures.** `fixtures/format-v1/` and `fixtures/format-v1-separators/` (built by version 1 binaries) and `fixtures/format-v0.1/` (pre-M5) are replayed in CI by `crates/bellwether-cli/tests/format_compat.rs`. `docs/format.md` documents the full version 2 segment layout with a worked segment, the roaring bitmap serialization (array and bitmap containers, several containers per bitmap) with vectors for a key in more than 4,096 row groups, conformance vectors and the minimal manifest. README gains an "Index kinds" section. `scripts/realdata.sh` checks counts against the decoded files (`CHECK counts`).
- Storage version 2 frozen: **M5** (WP14/B1, the second of two pull requests, ADR 028). Storage version 2 and record version 3 are the frozen format; a later byte change is a new version with a new fixture:
  - **Per-key time bounds and bitemporal keys are key specs.** `exact:symbol@ts[,counts]` keeps each key's `[min, max]` time per row group in its value record (`bitmap | [counts] | [bounds]`, with the all-null sentinel `(i64::MAX, i64::MIN)`, which overlaps no window); `temporal2:id@valid,known` has its own `bitemporal` layout of `(valid, known, row group)` versions; `bloom:id@0.01@ts` keeps a `bounds` segment under the bloom. `docs/format.md` documents the bytes, with conformance vectors for both folded layouts and their segments' blake3 (`crates/bellwether-core/tests/folded_conformance.rs`, which also checks them against an oracle over a Parquet file, merge widening, and every byte).
  - **Pre-M5 indexes fold.** An index whose bounds and `temporal2` are `schema.sidecars` reads and plans as written; its first build with work folds them into key specs, rebuilds them, and lists each fold (`sidecars_folded` in `index --json`, and in the human output); a sidecar no key spec can take stays a sidecar, still built and planned (`kept_legacy`), and a no-op `index` names the folds still pending (`fold_pending`). Where a kept `temporal2` sidecar leaves two bitemporal sources on one key, `asof`/`latest --known` take `--valid-by`/`--known-by` (MCP `valid_by`/`known_by`) to pick one, and refuse without them, naming both. A bloom's per-key bounds are a checksummed storage version 2 `keyed` segment (no longer the version 1 sidecar layout). `Error::UnsupportedShape` is gone.
  - **Propose, fix and price them.** `propose --key` takes a spec and, repeated, the specs applied beside it (MCP `propose.key` `sidecars`); `fix` builds, verifies and receipts them together. `why --valid-by <col> --known-by <col> [--valid <t>] [--known <t>]` (MCP `score.why` `valid_by`, `known_by`, `valid`, `known`) records a bitemporal run and prices `temporal2:<keys>@valid,known` against it; with no index it says to index first. MCP `observe.asof` takes `valid`/`known` (with `at` now optional). The proposal refusal `sidecar_not_proposable` is now `sketch_not_proposable`: a sketch is the only kind that cannot be proposed.
  - **Manifest.** `schema.columns[].data_type` is core's `ColumnType` JSON (`{"arrow": …}` for nested or dictionary types) and a CSV source records `source.dialect`; the version 1 spellings still read. A new index infers the widest decimal precision and scale across its files instead of refusing them.
  - **Records filled.** Verify fills `examples`, `uncomparable` (a key that cannot be compared no longer counts in `mismatched`), `totals` and `row_filter`; replay fills `configuration` and computes its catalog digest with `bellwether_source::catalog`; profile fills `sample_size`, `quantile_error` and `Lint.fix`. Two reconcile sides at different decimal scales are a schema error.
  - **Refusals.** `propose` checks a spec's time columns (bounds, a temporal version column, a bitemporal key's two clocks) and every spec proposed beside it as `index` does, so it writes no proposal `index` would refuse; `index` names a missing time column once with the dataset's columns; plan refusals name specs and columns as text; the `fix` header names every spec a proposal applies.
  - **Plan order.** When no order of whole files is a time order, `ScanPlan.order` lists the interleaved `(entry, row group)` read order and the plan says it is ordered.
  - **Fixed.** A lookback window priced on another column than the one recorded is converted to that column's unit (a `Date32` column no longer overflows).
  - **Fixtures.** The pre-M5 fixture moved to `fixtures/format-v0.1-pre/`, byte for byte; `fixtures/format-v0.1/` is rebuilt at M5 with every folded shape and a CSV index. `format_compat.rs` replays all three storage version 2 and 1 fixtures byte for byte and folds a pre-M5 copy.
- `bellwether-source-sql` (WP20, ADR 027): SQL tables as sources. `sql://<engine>/<schema>.<table>?db=...` roots over SQLite (rusqlite, in process), DuckDB, Postgres, and Flight SQL (ADBC), and SQL Server (ODBC, feature `odbc`); declared partitions or key ranges as units with an identity (a version column's maximum or a checksum of the unit's statistics); statistics as bounds from one aggregate query per unit; exact conversion to the dataset type; one snapshot per run, or every identity re-read and a change refused (`source_changed`); a `MeasuredScorer` (wall time, `EXPLAIN ANALYZE`). Through the facade, CLI, and MCP: reconcile a table against files (the certificate cites both catalog digests and the table's identity), `why` with every cost measured and no Replay recorded, `fix` verifying and then refusing with `attest_only` naming the `CREATE INDEX` to run (no Receipt). Folder-only verbs over a table refuse with `not_a_folder`. `scripts/sql-demo.sh` measures it on the NYC taxi data.
- `sketch` sidecar (B2): `index --key sketch:col[,col][,a+b][,p=14][,minhash=K]` keeps, per column or `+`-joined tuple per file, HyperLogLog registers (default precision 14) and optionally a MinHash signature, declared in `schema.sidecars[]` (kind `sketch`, additive to storage version 1; `docs/format.md`, "Sketch segments"). `bellwether sketch cardinality` (MCP `observe.cardinality`) reports approximate distinct counts with a 99.7 % interval, exact sketched and null rows, rows per value, files per value, and files that repeat a value with that count's detection floor (`duplicate_floor`; a sketch never asserts uniqueness), exact where a complete `exact` key spec holds the count (the index segments that scan reads are reported); `--transient` computes it from the files first. A column the dataset lacks is refused listing its columns, and with nothing named the refusal names a declaration over the dataset's id-like columns. `bellwether sketch overlap` (MCP `observe.overlap`) reports approximate Jaccard similarity, across two folders with `--with`. `why` gains the `sketch` column (and the funnel's kind column for a candidate on a sketched item), `reads` (the data files and row groups the diagnosis read, the files whose footer it read, and the exact-index segments it scanned), `sketch_unavailable` (a declared sketch whose segments are missing or damaged no longer stops `why`; re-declaring it with `index --key` sketches every file again, reported in `sketches_rebuilt`; `sketch cardinality` and `sketch overlap` refuse such a sketch with the same next step), and `--sketches-only` (MCP `sketches_only`), which answers from the manifest and the sketch segments and opens no data file, footers included. Lint `R-sketch-1` (low-cardinality key) fires from sketches. Every sketch number is labelled approximate; no planner path reads a sketch. The profiler's HyperLogLog moved to `bellwether_core::hll`.
- Text keys (B5; storage version 2): `text:<column>,tokenizer=words|trigram[,bloom=<fpr>]` indexes the case-folded tokens of a string column for `contains` (`like '%x%'`), `has` (`has_token`), and prefix match (`has_prefix`). Words are Unicode word boundaries (UAX #29), trigrams are 3-byte windows, both after full Unicode case folding from pinned crates (`unicase` 2.10.0, `unicode-segmentation` 1.13.3) whose versions every text segment records; a build on other versions refuses the segment, and `bellwether index` rebuilds exactly those keys, keeping the ledger and every other key. A words dictionary plans exact row groups; trigram and bloom plans are candidate sets and say the residual (`Predicate::Text`) is mandatory. Text lookups are ordinary workload runs (query kinds `contains`, `has_token`, `has_prefix`): `why --contains/--has/--prefix COL=TEXT` (or `--from <values> --mode contains|has-token|has-prefix`, or MCP `score.why` `text`) prices each text key as a candidate with its `text` column (distinct tokens, and when the column is too high-entropy for the key to pay), the `R-text-1` lint lands in the profile Evidence (naming only the keys for the unserved matches), the culprit names per match the text keys that serve it (`CulpritReason::Text`), and `fix` proposes, verifies on the rows the lookups ask for, applies, and receipts a text key like any other. `locate --contains/--has/--prefix` and MCP `observe.text` plan through it. `bellwether bench text --shape ledger|market` writes 1–4 KB documents with planted terms at 1% and 0.01% of rows; `scripts/text-funnels.py` prints the funnels in `docs/measured/2026-10-26-text.md`.
- `expr` keys (phase 5, B6): an index on a value derived from columns by a closed expression language (`json_get`, `lower`, `substr`, `cast`, `date_trunc`, `hash`; no user code), for filters and join keys that are a function of a column. `KeySpec::Expr` (spelled `expr:<name>=<expression>:exact`, `:exact,counts`, or `:bloom@<fpr>`; with counts, `bellwether count` on the expression is answered from the index) stores the normalized expression and per-function conformance vectors that every reader recomputes before trusting the key; its segments are ordinary exact or bloom segments over the virtual column, derived one row group at a time. A lookup matches an `expr` key only by normalized expression equality; any other expression, the virtual column's name, and non-locate lookups on an expression are refused, naming the keys that exist. The residual `Predicate::ExprIn` recomputes the expression per row. `why --from <keys>` with a key column named by an expression proposes the `expr` key, prices it from a transient derived column, and shows an `expr` column (rows whose expression is null / distinct derived values; `Candidate.kind_column`, the shared one-column-per-kind mechanism, with `Exactness`); `fix` certifies it over the workload's expression values. Lint `R-expr-1` recommends one when lookups supply an expression no `expr` key serves. `bellwether bench expr --shape ledger|market` writes a corpus with a JSON attribute column, key files for equality on a JSON path at three selectivities (and `date_trunc(ts,day)` on market), and exact ground truth; `scripts/expr-funnels.py` measures the funnel. Bytes and vectors in `docs/format.md` ("Expression keys").
