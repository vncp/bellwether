# bellwether

Work package WP9. The facade: one `Engine` over every engine crate, and the single code path the CLI and the MCP server share (ADR 010). Every operation is a method that returns a typed result; that result, serialized, is the CLI's `--json` output and what the MCP server returns. No formatting lives here: results carry integers, hashes, and the ledger records each call wrote or read, embedded whole with their hashes (`Written { hash, record }`, where `record` serializes to exactly the bytes at `ledger/<hash>.rec`).

```rust
use bellwether::{spec, Engine, EngineOptions, KeyFile, WhyRequest};

let engine = Engine::open("./orders", EngineOptions::default())?;           // index at ./orders/.bellwether
let why = engine.why(&WhyRequest { keys: Some(KeyFile::new("keys.parquet")), ..Default::default() })?;
engine.index(&[spec::parse("exact:order_id")?])?;                            // one manifest commit
let plan = engine.locate(&KeyFile::new("keys.parquet"))?;                    // a `plan` Evidence
println!("{} of {} row groups", plan.planned.row_groups, plan.row_groups_total);
```

Dependencies today: `types`, `core` (spec validation), `source` (sources, fingerprint policies, the catalog digest), `source-sql` (tables as sources, ADR 027), `store` (the index store, manifest, cache), `ledger` (the only write path), `build` (`index`, plans, the apply), `replay` (`why`, `fix`'s score), `verify` (`reconcile`, `fix`'s verify), `profile` (`why`'s fanout, lints, and Evidence).

## Operations

| Method | What it does | Records written |
|---|---|---|
| `Engine::open(root, options)` | Canonicalizes the data root once, the way the build does (a local folder; an object-store data root is refused because sources read local files only), and resolves the index location (default `<root>/.bellwether/`, or any store URL). The index store is opened on first write, so opening writes nothing. An existing index's source kind and root must agree. | none |
| `why(request)` | The dataset from footer statistics; with a workload (a Parquet key file, a bench workload directory, or a recorded workload hash), a replay (WP6) of the current configuration and each candidate key. Returns the funnel per candidate, the culprit, the recommended key, and every record. | per candidate an engine Proposal and its Replay |
| `index(specs)` | Build (WP4): declare `specs` in addition to the declared ones and index every live row group, in one manifest commit. Returns the committed sequence, segment counts, and completeness per spec. | none (a manifest commit) |
| `locate(keys)`, `latest(keys)`, `asof(keys, at)` | First list the folder: a file the index does not track, a tracked file that changed, or one that is gone is refused with an error naming `bellwether index` (invariant 1 over the folder: such a file would be silently left out of the plan). The check reads no file contents, whatever the fingerprint policy: each file is listed and `stat`ed, and a size or etag/mtime that differs from the manifest's is a changed fingerprint by definition. Only untracked files are fingerprinted. Under `full`, an in-place patch that keeps size and mtime passes this check and is caught when the planner verifies the full-content fingerprint of each file it plans. Then plan (WP4) with every declared spec complete at the current sequence; incomplete ones are listed as excluded. A temporal plan whose residual lacks `NotOlderThan` before `LatestPerKey` is refused (invariant 5). `at` converts to the timestamp column's unit exactly or is refused. | a `plan` Evidence citing the manifest's content hash and the key set's hash (the key set is stored in the cache, so the citation resolves) |
| `index_declared(declarations)` | `index` for `index --key` arguments as `spec::parse_declaration` reads them: key specs plus sidecars (`exact:symbol@ts` declares `exact:symbol` and per-key time bounds `bounds:symbol@ts`; `bloom:symbol@0.01@ts` likewise; `temporal2:id@valid,known` a bitemporal sidecar alone). The result lists each sidecar's completeness and any segment kinds this binary does not know. | none (a manifest commit) |
| `locate_window(keys, from, to, ts)` | `locate` restricted to `[from, to]` of a time column (`ts`, or the one column a complete bounds sidecar or timestamp range key on the key columns names): pruned by the key specs, the range keys on that column, and per key by every complete bounds sidecar. Residual `In` then `Between`. | a plan Evidence |
| `asof_bitemporal(keys, valid, known)` | Per key, the newest row by valid time among rows known by `known` and valid by `valid` (either optional; `latest --known K` is `valid = None`), through the one complete `temporal2` sidecar on the key columns. Plans exactly the winners' row groups. | a plan Evidence |
| `retained_manifests()` | The committed manifest sequences the index retains, each pinnable with `at_manifest`. | none |
| `cardinality(request)` | `count(distinct item)` for each item (a column, or a `+`-joined tuple such as `symbol+ts`) from the index's complete `sketch` sidecars: the **approximate** distinct count with its 99.7 % interval and relative standard error, the exact sketched and null row counts, rows per value (fanout), files per value, and files that almost certainly repeat a value (for a tuple, files where it is not unique). No data file is read (`files_read: 0`). Exact where a complete `exact` key spec on exactly the item's columns holds the keys (`exact_distinct`). When several complete sketches hold an item, the highest precision is read. An item no complete sketch holds is refused (`not_indexed`, naming the `sketch:` declaration) unless `transient`, which computes it from the files (replay's `TransientSketch`) and reports the files and row groups read. A folder whose files changed since the build is refused (`stale_index`). | none |
| `overlap(left, right, other)` | The **approximate** Jaccard similarity of two sketched items' value sets, each from a complete sketch of its folder (`other`, or this one), with its interval: MinHash when both keep signatures of one length, HyperLogLog inclusion-exclusion otherwise. Items of different column types or precisions are refused. | none |
| `propose(body, evidence, by)` | Writes a Proposal (Key, Layout, Rewrite). At least one evidence hash, each resolving to Evidence; key and layout columns must exist; rewrite texts non-empty; the engine's own proposer names (`RESERVED_PROPOSERS`: `engine`, compared trimmed and ignoring case) get a typed refusal (`ProposeResult::Refused`, CLI exit 3) and nothing is written. There is no score field and the facade adds none. | a Proposal |
| `propose_key(declaration, evidence, by)`, `propose_key_dry_run(..)` | `propose` (or `propose_dry_run`) of a key given as `spec::parse_declaration` reads an `index --key` argument (the CLI's `propose --key`, MCP `propose.key`). A key spec is proposed as `ProposalBody::Key`. A sidecar declaration (`temporal2:id@valid,known`, or `exact:symbol@ts`, whose bounds ride beside the key) gets the typed refusal `ProposeRefusal::SidecarNotProposable` (CLI exit 3, MCP `sidecar_not_proposable`) naming the `index` command that builds it and, for the bounds form, the key spec to propose alone; nothing is written. The refusal comes after every check a proposal gets (proposer, evidence, the key and time columns against the dataset), so both next steps work. `command` is `bellwether index <root> <flags> --key <declaration>`, every argument POSIX shell-quoted (`spec::shell_quote`), the flags those the engine was opened with that shape a build or locate the index (`--index`, `--format`, `--chunk-size`, `--schema`, `--fingerprint-policy`, `--partitioning` or `--path-template`), which the shared flag definition renders into `EngineOptions::source_flags`; the facade only assembles them. A library caller that sets source options without `source_flags` (a CSV dialect other than comma with a header, say) gets no `command`, and the refusal says so. A Proposal holds a key spec only, and replay prices key specs only (`docs/contract-v3.md`, entry 42). | a Proposal, or nothing |
| `reconcile(right, request)` | WP8 over the data root (left) and `right`, by key, optional latest-by, ignored columns, exact decimal totals by group (a float column as `col:dec(S)`: each value's exact binary value rounded half to even at scale `S`, summed as an `i128`, labeled `col:dec(S)` in the totals and the certificate's `totals_delta`; NaN or infinity is an error naming the key), or a deterministic sample. Anchored to this index's manifest when one exists; otherwise the verifier records manifest "0" and cites both sides' catalog digests. `memory_budget` (`--memory-budget`) sets the comparison state budget; the outcome's `memory` reports the passes and the rows read per side, and the human output prints them, the first 10 mismatching keys, and the exact totals. `reconcile_problems(request)` lists usage problems before any row is read (a `totals` column that is not a decimal or not a column, a zero budget); the CLI reports the first as a usage error, exit 2. CLI exit 1 when it does not pass. | a Certificate (stored even when it fails) |
| `fix(request)` | Score, verify, apply, attest, in that order and no other (below). | Replay, plan Evidence, Certificate, Receipt, realized Replay |
| `receipt(hash)` | The ledger's `explain` chain, with MISSING, WRONG KIND, and UNREADABLE flags, and every record that resolved. | none |
| `report(out)` | One self-contained HTML file (inline SVG and CSS, no scripts, no external resources) from ledger records only: the funnel per receipt, the fanout table per profile Evidence, realized against predicted bytes where a receipt has both. A record that cannot be read (tampered, newer, malformed) is skipped and listed. | none |
| `folder_status()` | The folder check `locate`, `latest`, `asof`, and `fix` run first, as data: the untracked, changed, and missing files (sorted paths) and the current sequence, or `None` for a folder never indexed. The one source of the lists the stale-index error (`Error::StaleIndex`) carries. | none; never creates the index location |
| `propose_dry_run(body, evidence, by)` | Every check `propose` runs; returns `ProposeResult::WouldWrite` with the Proposal and the hash the ledger would name it by (equal to the real write's under a fixed clock), or the same refusal or error. | none; never creates the index location |
| `apply_dry_run(certificate)` | The apply tier's gate (passing, current sequence, for a key the data still the data certified) and the kind refusals; returns `FixOutcome::WouldApply { sequence, expected }` or the same refusal or error. | none; never creates the index location |
| `findings()`, `receipts()`, `scorecard()` | Ledger views (the MCP resources and `bellwether ledger`): the newest profile Evidence per root with the receipts citing it; every receipt with its `explain` chain status; per rule id, proposals, certificates passed and failed, and receipts. Scorecard attribution: a proposal counts under each rule id a lint in its cited profile Evidence raises on one of its columns (a rewrite: every rule its Evidence raises), else under `unattributed`; certificates and receipts count under their proposal's rule ids. Unreadable records are listed and skipped. | none; never creates the index location |

## Tables (`sql://` roots, ADR 027)

`Engine::open` takes a table root, `sql://<engine>/<schema>.<table>[,...]?db=<connection>...` (`bellwether-source-sql`), as well as a folder. A table has no folder to hold the ledger, so `EngineOptions::index` is required (`InvalidArgument { field: "index" }` otherwise); the file options (format, chunk size, fingerprint policy, partitioning) and `at_manifest` are refused. `root()` is `sql://<engine>/<tables>`: the connection parameters never reach a result or a record.

- `reconcile` takes a table on either side (`right` may be a `sql://` root too). A table compared with a folder is read at the folder's dataset types where the two differ only in decimal scale, time unit, or integer or float width, every value converted exactly or refused (the data root's `--schema` wins). The certificate cites both catalog digests and the table's source identity; `ReconcileResult::tables` reports each table's units, rows, and the snapshot held or the identity re-read that stood in for one.
- `why` works as over an unindexed folder, but every byte count is measured: `WhyReport::exact` is `false`, `model` is `measured: logical bytes from per-unit aggregates`, each candidate's Replay is computed with every cost `exact: false` and returned with the hash it would have, and no Replay is recorded (the ledger keeps exact current costs only). Proposals and the profile Evidence are recorded.
- `fix` scores (`Score::Measured`, unrecorded), verifies, writes the Certificate, and applies the gain gate on the measured costs (`nothing_to_gain` unless `allow_no_gain`), then refuses with `Refusal::AttestOnly { certificate, target, run, proposed_rewrite }`: `target` is the table root; for a key, `run` is the `CREATE INDEX` per table the engine wrote; for a rewrite, `run` is empty and `proposed_rewrite` is the agent's `after` text, never run and labeled as the agent's. No Receipt is written. `fix --certificate` and `apply_dry_run` re-score (unrecorded), gate, and refuse the same way, and the dry run writes nothing. Attest-only applies when the data root is a table; a rewrite over a folder is `no_replay` whatever its outputs.
- `index`, `locate`, `latest`, `asof`, and the window and bitemporal lookups refuse with `Error::NotAFolder`.
- Every table source an operation opens is registered with the engine and ended before each record is written (`finish_tables`): with a snapshot, nothing to check; without one, every unit's identity is re-read and a change is `Error::SourceChanged`, so nothing over a changed table is recorded.

| `format`, `chunk_size` | `--format`, `--chunk-size` | Parquet, CSV, or JSON lines; the text chunk size for new files. `--chunk-size` with Parquet is a usage error (exit 2) for every verb, at option parsing (`EngineArgs::options`). |

Needed when files store a column at different decimal scales or time units; a value that does not fit the inferred type is refused with an error naming `--schema`. | `partitioning` | `--partitioning none\|hive`, `--path-template <PATTERN>` | When a new index is built, by `index` or by `fix`'s apply stage (one set of build options, `Engine::build_options`), or an unindexed folder read: `hive` makes `name=value` directories below the root columns, and a path template (`Partitioning::Template`, for example `{day:date}.parquet`) makes its placeholders columns, for every source format. | `clock` | `--clock` (hidden) | A fixed RFC 3339 time for every record's `created_at` and for ages, so two runs over the same inputs write byte-identical records, certificates included (the verifier's `CertificateContext::clock`; the workload's cache age is measured to the clock). The ADR 010 test runs the CLI and the in-process facade under one clock and compares bytes. |
| `source_flags` | set by the flags themselves (`bellwether_mcp::EngineArgs::options`) | The flags above that shape a build or locate the index, one argument per element, paths absolute: what the `bellwether index` command in a `SidecarNotProposable` refusal carries. `None` for a library caller. |

## `why`

- **Writes.** `why` always computes the profile and returns its Evidence (`evidence`). It writes the Evidence, and the profile's cached footers and fanout table, to the index location when that location exists or can be created (`recorded: true`). Otherwise, for example on a read-only folder with no `--index`, it profiles in memory, with the index's manifest when one can be read, writes nothing, and returns the Evidence with `recorded: false` and one line naming `--index`; it still succeeds. With a workload it also writes the key sets, Proposals, and Replays; Proposals cite a recorded Evidence, so on an unwritable location the error is one line naming `--index`.
- **Profile.** `bellwether_profile::profile` with `ProfileOptions::for_source` describing the source `why` built (`parquet`, or the text format with its effective chunk size), `--columns` as the candidate columns, and a bench workload as the profile's workload, so its key columns are the profile's supplied columns (the lints' partner order). A key file's columns, or a recorded workload's run columns, reach the profile as `ProfileOptions::supplied_columns` (contract v3 backlog #35), so with any workload the lints order composites by what lookups supply and state no assumption. The profile lists every column it does not measure with its reason (`profile.skipped`, and `not candidates` in the human output); a nested column is listed as nested, and is never a candidate. Under a fixed clock (`--clock`) the profile recomputes its cache rather than reusing it, so no input carries a wall-clock age.
- **Dataset.** Files, live row groups, rows, and bytes come from the replay crate's catalog: the manifest when an index exists, else discovery. Footers only. In an indexed folder, files that landed after the last build are listed in `untracked` and counted in the dataset totals; the costs cover the files the index tracks, so the output says to run `bellwether index` first.
- **Candidates.** The exact key on each run's own key columns, unless it is already current: the floor, which selects exactly the row groups holding a queried key, the least any row-group index can read for those runs. Then the profile's measured columns and composites that serve a run by point lookup, in the profile's rank order, at most `max_candidates` (`--max-candidates`, default 8). Measured keys that serve no run are listed in `not_serving`. A composite that serves a run only by prefix (led by the run's whole key) is not replayed: it selects at least the row groups of the exact key on the run's columns, the floor, so it can never read less.
- **Proposals and replays.** Each candidate is written as a Proposal by `engine` and scored by `Replayer::record`, which computes the replay and writes it at once. Every Replay carries `inputs` (the catalog digest) and, being a key replay, no `model` (contract v2.1). Every Proposal cites the profile Evidence.
- **Funnel.** Costs are summed over runs: files, row groups, bytes, each an exact sum of row-group statistics.
- **Culprit.** With a workload, the layout (`layout`) when every priced configuration, the floor included, reads at least `LAYOUT_BOUND_FRACTION` (0.75) of the row groups the runs span and the dataset has at least 2 row groups: each value is spread over nearly every row group, so no index helps. It names the lowest-fanout measured column (`lowest_fanout`). Else the highest-confidence `batch_stamp_key` or `low_selectivity_single_column` lint on a column the workload or a current spec uses (`lint`); else the workload's key columns when no current spec serves them (`no_index_serves`), or the serving current spec's columns. Each carries the profile's measured fanout of its columns.
- **Recommendation.** The candidate with the fewest bytes over all runs (ties: fewer columns, then candidate order), only if it reads fewer bytes than the current configuration.
- **Workloads.** A key file is recorded as a one-run workload (run id `keys`) in the store's cache; its hash is in the result, and `fix` takes it.
- **Temporal pricing.** `latest_by` (`--latest-by <ts>`) records the key file's run as a `latest` lookup, or an `asof` lookup at `at` (`--at`), in the workload's `query_kind` (contract v3 backlog #14). The candidates gain the temporal floor `temporal:<run columns>@<ts>`; every candidate is priced under the requested lookup (`proposed`) and under point lookups (`locate`), and the recommendation is chosen by the requested lookup (`Recommendation.lookup`). A temporal candidate's predicted cost equals what `latest` or `asof` plans once that key is built, and the current cost equals what they plan now: through a serving temporal key, or for a lookback through per-key bounds (`exact:symbol@ts`) or the window column `asof --lookback` takes, never a full scan when the index can prune. When the current index plans the lookup on another time column than `latest_by` (a temporal key on `ts` with `--latest-by day`), `at` and the lookback would be measured in the wrong unit, so the request is refused (`InvalidArgument { field: "latest_by" }`, CLI exit 2) naming both columns and the `--latest-by` to pass. `ts_column` (`--ts <col>`) with `at` and `lookback` means what it means on `asof`: the window `[at − lookback, at]` is planned on that column (for example when range keys on two time columns leave the window column ambiguous), so the key file's run is recorded as that window run and priced as `asof --at --lookback --ts` plans it; `latest_by` must name the same column, and a key file (`--from`) is needed. Candidates are de-duplicated by their full spec, time column included. A recorded workload (`--workload`) is priced as its runs were recorded; asking it for another lookup with `--latest-by` is refused. `mode` (`--mode locate|latest|asof`) states the lookup; without it, `--at` implies `asof`, `--latest-by` alone `latest`, and neither `locate`. `latest` needs `--latest-by`, `asof` needs `--latest-by` and `--at`, and `locate` takes none of them; an inconsistent combination is refused before any work (`WhyRequest::lookup_mode`, CLI exit 2). `lookback` (`--lookback N`, units `s`, `m`, `h`, `d`, `w`, calendar time, trading-day calendars out of scope; a bare integer for an integer timestamp column) prices every version of each key in `[end − N, end]`, `end` being `--at` or the key's newest version, instead of one version per key: the run records `lookback` in the timestamp column's unit (contract v3 backlog #38), and both planners select every live row group holding a version of a key in its window (`Lookup::Window`), with the residual `In(keys)` plus `Between(ts, at − N, at)` (asof) or `NotOlderThan(newest − N)` per key (latest). A length that is not a whole number of the column's unit, or longer than the column can measure, is refused, never rounded or clamped (`InvalidArgument { field: "lookback" }`, CLI exit 2), with the lookbacks to pass (`36h` on a date column: `1d` or `2d`; the longest one). `WorkloadInfo.lookback` and `Recommendation.lookback` report it.
- **Sketches (B2).** Where the index holds complete `sketch` sidecars, the report's `sketch` column lists each sketched item's approximate distinct count, bound, and rows per value (exact where an `exact` key spec holds the count), read from the sketch segments; a candidate whose columns are a sketched item carries it as its `kind_column` (`≈` value, `Exactness::Measured { model: "sketch.hll" }`, the error bound in the label). The low-cardinality-key lint `R-sketch-1` (`bellwether_profile::lints::low_cardinality_key`) is computed from the same sketches and joins the profile's lints before its Evidence is built. `reads` counts the data files and row groups the diagnosis read (footers are metadata and not counted). `sketches_only` diagnoses from the sketches alone: the profile's key-read pass is skipped, `reads` is zero, and `from_sketches` is set; it needs a complete sketch (`not_indexed` otherwise) and refuses a workload or `columns` (`invalid_argument`, saying which to drop). No sketch number reaches a plan, a replay, or a recommendation.

## `fix`

1. **Score.** For a Key proposal, the workload (`--workload <hash>`, which `why` prints) is replayed under the current specs plus the proposed one by `Replayer::record`, computed immediately before the Replay is written: no caller-supplied cost or `Scored` value reaches the ledger. A Rewrite has no defined replay (contract v3 backlog #2) and records `not_scorable`. A Layout is refused (`layout_not_applicable`; layout apply arrives with evolve). A Key whose replay predicts no saving (proposed bytes not below current bytes, summed over runs) is refused right after the score with `nothing_to_gain` (exit 3), citing that Replay; nothing else is written. `allow_no_gain` (`--allow-no-gain`) goes on; the apply tier (`--certificate`) applies the same gate to its re-score.
2. **Verify** against the current manifest (`manifest_before`). Key: the full scan, restricted to the workload's keys (each float key element under both zero encodings, as the planner probes them), is reconciled against a source exposing only the row groups of the hypothetical plan (the union of each run's plan with the proposed spec's transient segments), coverage `Workload`; that plan is written as a `plan` Evidence and cited by the certificate. When a run asks for some rows of its keys (an `asof`, a lookback, or a window), both sides compare only the rows some run asks for (`ReconcileSpec::row_filter`), and the human output prints them. Every bound comes from the workload or the data, never from the index under test: a window's ends and an `asof`'s instant and lookback are the run's own, on the column the lookup is planned on, and a `latest` lookback's window `[newest − N, newest]` uses each key's newest time read from the left side (the full scan; one time per looked-up key). An index whose bounds disagree with the data (a bounds sidecar whose newest time for a key is too old or too new) plans other row groups than those windows need, so its certificate fails. When every run is a `latest` or `asof` on one column, the newest kept version per key is compared (`latest_by`). A plain `latest` workload is compared by `latest_by` alone, so a key whose versions all have null times stays uncomparable (ADR 014). The filter is a function of the workload (cited by the coverage) and the left side's data (cited by its catalog digest); the certificate cannot state it inline (contract v3 backlog #44). The verifier lists a file's row groups densely by position, so a row group outside the plan is listed with zero rows and no statistics and reads as an empty batch. Rewrite: the before and after outputs the caller names, coverage `Full`; the rewrite's invariant travels in the proposal the certificate cites and in the result.
3. **Apply**, behind one gate: the certificate passed, was computed against the current sequence, and, for a Key, still describes the data: the data root's catalog digest (`bellwether_source::catalog::unindexed` over every file and row group now, exactly as the verifier computes the left side) equals the left-side digest the certificate cites (else `certificate_failed`, exit 1, `stale_manifest`, exit 3, or `data_changed`, exit 3: run `fix` again to re-verify). This catches a file that lands or changes without a commit. A key that is already complete at the current manifest is refused `nothing_to_apply` before the proposal is scored, in `fix --proposal` (unless `--verify-only`), `fix --certificate`, and `apply_dry_run` alike, so the dry run and the apply agree and the refusal writes nothing. The build must then commit exactly `before + 1`: no commit at all is `nothing_to_apply` (another writer completed the key in between) and any other sequence is `concurrent_commit` (another commit landed first; the build crate has no expected-base precondition, so this is detected, not prevented): the key is built and serves lookups (no re-index is needed) but cannot be attested, and retrying will not attest it: a retry finds the key already complete (`nothing_to_apply`). Both withhold the receipt (exit 3).
4. **Attest** with `Ledger::put_receipt`. Then the same proposal is replayed at `manifest_after` and that Replay is written: the realized cost, which `report` pairs with the receipt's predicted one. If that replay fails, the receipt stands: the outcome is still `applied` (exit 0) with a `warning`.

On an indexed folder, `fix` first runs the plan-time folder check, so a stale index is refused naming `bellwether index` before any work. A failing certificate writes no receipt and names its counts; `verification` in the result carries the typed outcome, including what each side read. `fix --certificate <hash>` is the apply tier: the gate runs before anything is written, the proposal is re-scored on the workload the certificate covered, then applied and attested. A passing Rewrite is refused at attest (`no_replay`, exit 3): a receipt cites a replay, and rewrites have none yet. `--verify-only` stops after the certificate.

## Errors

Every public method returns `Result<_, bellwether_types::Error>`. The refusals an agent or a script acts on carry their facts as data, so neither surface reads prose, and their messages name no surface's flags (the CLI appends its flag, the MCP server its field name): a folder that changed since its index was built is `Error::StaleIndex { untracked, changed, missing, message }`; a hash of the wrong kind (a proposal passed where a certificate is applied, a non-evidence hash cited) is `Error::WrongKind { hash, expected, found }` and an absent one `Error::RecordNotFound { kind, hash, place }`, `kind` a `HashKind` naming the argument; a proposal scored without its workload or rewrite outputs is `Error::NoWorkload { proposal, field, needs }`; a lookup over a folder with no index, or none of the kind it plans with, is `Error::NotIndexed { root, operation, needs }`; and an argument that cannot be used (an empty proposer, no evidence, an instant that is not one, an unreadable key file or output folder) is `Error::InvalidArgument { field, reason }`. An internal panic is caught at the method boundary and returned as an error naming the issue tracker, so no panic reaches a caller. The crate denies `unwrap` and `expect`.
